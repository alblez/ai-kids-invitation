# Make it yours

This page lists every file and field you need to change to turn this invitation into your own child's party.

## Files to edit

### Party details

Open `src/components/Details.astro` and update the `partyDetails` object near the top:

```ts
const partyDetails: PartyDetails = {
  date: 'Saturday, June 13, 2026',           // your party date
  time: '3:00 p.m. to 6:00 p.m.',            // your party time
  venue: 'Chelsea Piers Field House',         // your venue name
  address: '62 Chelsea Piers, New York, NY 10011',  // your address
  addressNote: 'Demo address — use your own party location',
  addressEncoded: encodeURIComponent('Your Venue, Your Address'),
};
```

The `addressEncoded` value is used in the Google Maps and Waze links. Make sure it matches your real address.

### WhatsApp number and message

Open `src/components/Rsvp.astro` and update:

```ts
const whatsappNumber: string = '15555550123';  // your number, country code, no +
const whatsappMessage: string = encodeURIComponent(
  "Hi! We'll be at Gael's party. See you there!"  // your message
);
```

### Child's name and age

The child's name and age appear in several components. Search for "Gael" and "4" across these files:

- `src/components/Hero.astro` — the hero name, subtitle, and age badge
- `src/components/Details.astro` — the heading and speech bubble
- `src/components/Activities.astro` — activity descriptions and captions
- `src/components/Rsvp.astro` — callout text, heading, paragraph, captions, WhatsApp message, and footer

### Site URL and metadata

In `astro.config.mjs`, change the `site` field to your deployment URL:

```js
site: 'https://your-project.vercel.app',
```

In `src/layouts/Layout.astro`, update the `title` and `description` defaults:

```ts
const {
  title = 'Your Child is turning N!',
  description = "You're invited to the party. Come celebrate with us!",
} = Astro.props;
```

## Swap images

The invitation uses cartoon illustrations in four directories:

| Directory | Images | Sizes |
|---|---|---|
| `src/assets/hero/` | Swing pose, revealed portrait, web strand, sky plate | Various (see filenames) |
| `src/assets/details/` | City plate, Gael on rooftop | 1184x896 (city), 500x625 (Gael) |
| `src/assets/activities/` | Four costume poses | 560x672 each |
| `src/assets/rsvp/` | Reaching pose, high-five pose | 560x672 each |

When replacing images:

1. **Keep the same dimensions.** The animation coordinates (swing path, burst origin, route endpoints) are measured in the images' pixel space. Changing dimensions means re-measuring those coordinates in the component code.
2. **Keep transparency.** All character images are transparent PNGs or WebPs composited over the dark page background (`#0f172a`). Check that hair edges look clean on dark.
3. **Use WebP.** Export at quality 85, preserving the alpha channel. The existing images total under 200 KB per section.
4. **Master PNGs go in `src/assets/source/`.** These are tracked in git but never imported by Astro, so they are not shipped to visitors. Keep your editing masters here.

If you change the Activities poses, they must stay aligned: same canvas size, same face position, same foot baseline. The costume-change wipe effect depends on pixel-level registration. See [image validation](5-image-validation.md) for how alignment was checked.

If you change the RSVP poses, the burst effect origin is measured from the R01 pose's palm position (33.8% / 40.2% of the canvas). Update the CSS custom properties in the component if your character's hand is in a different spot.

If you change the Details images, the SVG route coordinates (fingertip at 588,477 and door marker at 768,594 in plate units) need to match your new artwork. These are hard-coded in the inline SVG inside `Details.astro`.

## Regenerate the OG image

The WhatsApp preview image (`public/og.jpg`) is generated by a script:

```sh
node scripts/generate-og.mjs
```

This produces a 1200x630 JPEG using Satori and resvg. Edit the script to change the text, colours, or layout. The script runs on macOS (it uses `sips` for the final JPEG conversion).

### WhatsApp OG caching

WhatsApp caches the preview image by URL. After changing `og.jpg`, visitors who already received the link will still see the old image. To force a refresh, bump the version parameter in `src/layouts/Layout.astro`:

```ts
const ogImage = new URL('/og.jpg?v=3', Astro.site);  // was ?v=2
```

## Deploy

The site is configured for Vercel:

1. Push your repo to GitHub.
2. Import it in Vercel. It auto-detects Astro and configures the build.
3. Your site will be live at `your-project.vercel.app`.

No adapter or server configuration is needed: this is a fully static site.

## Test on a real phone

After deploying, test on an actual phone:

1. Open the link from WhatsApp. Check that the preview image, title, and description appear.
2. Tap the WhatsApp RSVP button. Verify it opens a chat with the correct number and pre-filled message.
3. Tap Google Maps and Waze. Verify they open to the correct address.
4. Scroll the whole page. Check that animations play, the experiment works, and the high five responds to taps.
5. Check with the phone's "reduce motion" setting on. The page should show static compositions with no animation.

Browser emulation does not replace this. Link previews, deep links, and touch interactions behave differently on real devices.

## Privacy checklist

Before making the repository public or sharing the link:

- [ ] **No real photos committed.** The `src/assets/source/` directory should contain only cartoon illustrations, never photographs of your child. Reference photos used for image generation should stay outside the repository entirely.
- [ ] **Grep for your phone number.** Run: `grep -r 'your-phone-digits' .` — make sure your real number does not appear anywhere.
- [ ] **Grep for your address.** Run: `grep -ri 'your street name' .` — check that your home address is not in any file.
- [ ] **Check the rendered page.** Open the live site and read every line of text. Metadata is easy to miss.
- [ ] **Check the OG image.** Share the link in a private WhatsApp chat with yourself. Read the preview text and look at the image.
- [ ] **Check git history.** If you committed real details and then changed them, the old values are still in the history. Consider squashing or starting fresh with `git checkout --orphan`.
- [ ] **No private paths in docs.** Search the repository for your home directory path to make sure it does not appear in any committed file.
